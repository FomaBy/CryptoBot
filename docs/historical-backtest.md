# Исторический прогон ACS

R-025 / B-023. В кабинете пользователь выбирает USD preset, проверяет точные UTC границы последних 14 дней и запускает расчёт. Результат хранится под его аккаунтом. Недостающая история не сдвигает период автоматически: сценарий доступного участка требует отдельного выбора.

Производитель остаётся private ACS: `GET /crypto/api/backtest/v1` читает существующий `strategy-history.db` через read-only SQLite snapshot. Никаких provider/LLM вызовов или изменений глобальных стратегий. Public CryptoBot содержит только строгий consumer, аккаунтное хранение и интерфейс. Исторические labels, wallet feed и private JSON не экспортируются. Pons принадлежность устанавливается по записи прошлого, не по текущему списку выживших токенов.

## Правила и пределы вывода

Исходный профиль — текущий ACS `ENTRY65_DEX` с выходом C: 75% исходной позиции при ×1,5; остаток при ×2, trailing 20% или времени runner; до первой продажи stop 40% и 30 минут. Полный source profile/hash показывается отдельно от hash исполняемой модели. Архив не позволяет восстановить все migration/route/knife/devDump/hard gates. Численный сценарий поэтому всегда сохраняет отметку недостаточности доказательств исполнимости и не считается точным воспроизведением live-стратегии, untouched OOS или разрешением торговли.

Входной сигнал берётся из сохранённого entry rating v2 ≥65 и canEnter с известным отсутствием recorded rejects. Цена входа — последующее наблюдение после 5 секунд с повторной проверкой известных guards. Выход тоже исполняется только на следующем доступном наблюдении после задержки. Нет интерполяции, цены ATH, современных рейтингов или восстановления пропусков будущими свечами. Один пропущенный первый сигнал не заменяется задним числом более удачным входом.

Комиссия 1%, creator-tax 10%, slippage 1% на сторону и gas $0,03 — **сценарные параметры существующего ACS**, не проверенный тариф каждого токена. Impact по quote liquidity — приближение, не исполнимая глубина. Отдельно показаны account overlay limits: до трёх позиций, 20% gross exposure, дневной лимит и желаемый размер входа каждого preset. Это параметры исследования, не утверждённые live caps.

USD cash/расходы/PnL учитываются целыми единицами 10⁻⁸ USD; расходы округляются вверх, поступления вниз. Цена/количество модели приближённые и не являются on-chain base units. Gas резервируется на две продажи, каждая частичная продажа оплачивается отдельно. Исчезнувшая ликвидность, большой пропуск или остаток в конце периода получают консервативное нулевое списание отдельно от realized PnL; фиктивной продажи нет. Economic net неизвестен, пока не распределены инфраструктурные расходы. Baseline «не торговать» имеет trading PnL 0.

## Ограничения и хранение

Рабочий поток отдельно от HTTP event loop; один активный ACS worker, deadline 90 секунд, V8 heap limit 256 MiB. Это не обещание ограничения всей native SQLite RSS. Исторический SQL predicate выбирает кандидатов по условиям на тот момент, затем читает их последовательности по индексу. Максимум 500 кандидатов / 250 000 наблюдений; превышение явно помечает усечённый расчёт. Отчёт ограничивает отображаемый ledger 200 сделками и equity примерно 300 точками; счётчики и truncated flags сохраняются. Daily coverage относится ко всему доступному архиву, feature metrics — к выбранным историческим кандидатам; покрытие не доказывает отсутствие сетевых пропусков.

Source revision, dataset hash, source profile hash, model hash, costs, requested/effective UTC interval и generatedAt замораживаются в сохранённом отчёте. Dataset hash обозначает прочитанные наблюдения, но не сохраняет их полную копию: после retention/изменения источника точный повтор может стать невозможен. Сохранённый отчёт не обновляется автоматически.

Bot API требует root session, POST/DELETE — Origin и CSRF. Idempotency key связан с аккаунтом и frozen params; другой аккаунт не читает/удаляет результат. До 20 отчётов на аккаунт, 500 всего, один активный на аккаунт и два ожидающих источника глобально. Истёкшая 120-секундная lease становится interrupted; новый процесс не сбрасывает живую работу другого процесса. SQLite schema additive, backup согласован через SQLite API; rollback кода не откатывает свежие пользовательские данные.

Проверки и фактические production результаты записываются в [execution log](execution-log.md), а не предполагаются по наличию кнопки.
