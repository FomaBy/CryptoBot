# Robinhood Crypto: справочное исследование первоначального варианта

**Архив решения:** после этого исследования пользователь уточнил **Robinhood Chain + Pons**, не Crypto EU. Ниже сохранены выводы о другом продукте; US-only API не блокирует текущий Chain/Pons план.

Дата исследования: **2026-10-08** по контексту рабочей сессии. Проверены доступные официальные страницы Robinhood; это снимок доступной документации, а не подтверждение состояния конкретного аккаунта или будущих запусков. Многие страницы не содержат даты обновления. Дата обхода поискового индекса не считается датой вступления условий в силу. Авторизованные API-запросы и торговые операции не выполнялись; credential-файлы не читались.

## Решение для выбранного аккаунта

Пользователь подтвердил **Robinhood Crypto EU**, бюджеты в **USD**, кошельки — позже. **Автоматическое исполнение через описанный ниже Crypto Trading API для этого аккаунта сейчас нельзя считать реализуемым:** официальная справка ограничивает API клиентами Robinhood Crypto в США. API v1 поддерживает ордера без fee tiers, v2 — с fee tiers; чтение аккаунтов, остатков, ордеров, продуктов и котировок доступно в обеих версиях. Ключи создаются в web classic с выбранными разрешениями. Наличие EU-приложения не снимает ограничение US-only. [Официальная справка Crypto Trading API](https://robinhood.com/us/en/support/articles/crypto-api/)

Для американского аккаунта указаны, среди прочего, возраст 18+, SSN, допустимый адрес проживания в США и гражданство США, постоянное резидентство либо действующая американская виза. Часовой пояс компьютера и гражданство сами по себе не определяют eligibility. [Требования к открытию US-аккаунта](https://robinhood.com/us/en/support/articles/what-you-need-to-get-started/)

EU-продукт обслуживает Robinhood Europe, UAB; официальная EU-справка описывает сделки и лимитные цены в EUR. Доступ к нему и доступ к американскому API — разные возможности. Полный актуальный перечень условий допуска в EU в этом исследовании не верифицирован; наличие пользовательского EU-аккаунта принято из его ответа. Публичную документацию аналогичного EU Crypto Trading API найти и подтвердить не удалось. Это ограниченный вывод о доступных источниках, а не доказательство отсутствия любых частных интеграций. [EU crypto trading](https://robinhood.com/eu/en/support/articles/crypto-trading/), [EU regulatory disclosures](https://robinhood.com/eu/en/support/articles/regulatory-registrations-and-disclosures/)

**Рекомендация:** сохранить Robinhood EU как выбранный контекст и реализовать анализ, сигналы, журнал решений и paper trading. Включение исполнения заблокировать до подтверждённого официального EU API. Альтернативы — EU-площадка с официальным API или DEX-исполнение — требуют отдельного выбора пользователя; автоматически менять площадку нельзя. USD оставить валютой планирования и отчётности; EUR-котировки пересчитывать с сохранением курса, времени и источника FX. Расходы конвертации учитывать отдельно.

## Подтверждённый технический контракт US API

Следующее относится к US API, **не к EU-аккаунту пользователя**. [Официальная API-документация](https://docs.robinhood.com/crypto/trading/)

| Область | Документированный контракт |
|---|---|
| Подпись | Ed25519; заголовки `x-api-key`, `x-signature`, `x-timestamp`; подписывается конкатенация `api_key + timestamp + path + method + body`; timestamp действителен 30 секунд. |
| Каталог | `GET /api/v2/crypto/trading/trading_pairs/`; пагинация; поля `symbol`, `asset_code`, `quote_code`, `asset_increment`, `quote_increment`, `max_order_size`, `min_order_amount`, `status`, `is_api_tradable`. |
| Исполнение | Только USD-пары с `is_api_tradable=true`; типы `market`, `limit`, `stop_loss`, `stop_limit`; UUID `client_order_id` для идемпотентности. |
| Счёт | v2 holdings/orders требуют `account_number`; accounts возвращает buying power, статус и fee tier. |
| Котировки | Best bid/ask исключает размер и комиссию; estimated price оценивает конкретный объём и расходы, но не гарантирует цену исполнения. |
| Ограничения | 100 запросов/минуту на аккаунт, burst 300; token bucket; настройки могут различаться по endpoint и изменяться. |

В просмотренном контракте не подтверждены sandbox, WebSocket, исторические OHLCV или публичная история сделок произвольного клиента. Не закладывать их наличие в MVP.

Инженерные рекомендации: подписывать ровно отправляемые байты JSON и путь с параметрами; синхронизировать часы; использовать Decimal; не логировать секреты. На старте использовать только read-only credentials. Для будущего адаптера нужны ограничитель запросов с запасом, backoff, обработка пагинации, сверка состояний после неопределённого ответа и запрет повторной отправки с новым id при неизвестном результате предыдущего ордера. Успех отмены запроса ещё следует сверить с окончательным состоянием ордера.

## Мемкоины и минимальные размеры

US-справочник содержит, например, DOGE, SHIB, PEPE, PNUT и TRUMP, однако доступность различается по интерфейсу, маршрутизации и региону. Отображение графика не означает возможность торговли; справочная таблица интерфейсов не является списком разрешённых API-пар. [Crypto availability](https://robinhood.com/us/en/support/articles/coin-availability/)

В проекте необходимы два множества: исследуемые токены и реально исполнимые инструменты выбранной площадки. Их пересечение вычисляется динамически. Список мемкоинов не следует зашивать как обещание доступности. Для внешних токенов идентичность задаётся сетью и contract/mint address; совпадения тикера недостаточно. Пока кошельки отложены, модель данных может хранить эти идентификаторы без подключения кошельков.

US-справка указывает минимумы **$0.01** для market maker routing и **$0.03** для smart exchange routing. Она также описывает защитные ограничения market-ордеров, возможную отмену неисполненного ордера через две минуты и риск неисполнения limit/stop-limit. Это общая справка продукта, не замена проверке конкретной пары и версии API; особенно нельзя переносить эти минимумы на EU. [Buying and selling crypto](https://robinhood.com/us/en/support/articles/cryptocurrency-investing/)

Предлагаемая проверка перед сделкой: актуальная разрешённая пара → доступный баланс → размер/шаг → свежая цена с расходами → лимит риска → отправка. Если минимальный допустимый размер больше бюджета риска, сделку пропустить; автоматически увеличивать бюджет нельзя.

## Комиссия, spread и реалистичная экономика

В доступном US Fee Schedule, идентификатор которого начинается с `20260622`, для exchange routing при объёме $0–$10K за 30 дней указаны taker **0.95%** и maker **0.50%**. Для market maker routing торговая комиссия указана нулевой. Это тариф американского продукта, а не EU. [Официальный RHC Fee Schedule](https://cdn.robinhood.com/assets/robinhood/legal/rhc-fee-schedule.pdf)

Справка отдельно предупреждает о постепенном rollout maker/taker и сообщает, что v2 API пока тарифицируется как taker до завершения этого rollout. v1-ордера не засчитываются в объём fee tiers. Поэтому limit-ордер сам по себе не позволяет обещать maker-тариф. [Crypto fee tiers](https://robinhood.com/us/en/support/articles/crypto-fee-tiers/)

Расчётный пример, не прогноз: покупка на $100 при 0.95% стоит примерно $0.95 комиссии; продажа на близкую сумму добавит примерно столько же. Около $1.90 на оборот возникает ещё до spread, изменения цены и проскальзывания. Для стратегии с небольшой ожидаемой прибылью это существенный барьер. Симулятор должен отдельно моделировать комиссию, bid/ask, slippage и задержку; отсутствие торговой комиссии не означает нулевых полных расходов. Robinhood направляет заявки внешним поставщикам ликвидности, поэтому нельзя считать его котировку гарантированным исполнением на собственном биржевом стакане. [Crypto order routing](https://robinhood.com/us/en/support/articles/crypto-order-routing/)

Для EU официальный публичный тариф: **0,50%** от EUR notional с минимумом **€0,01** за исполнение; условия промо и фактический тариф аккаунта требуют проверки. Источник: [EU crypto trading](https://robinhood.com/eu/en/support/articles/crypto-trading/). US-проценты выше использовать только как иллюстрацию и спецификацию US-адаптера, не как значения по умолчанию EU paper trading. Если точные расходы неизвестны, результат симуляции маркировать как предварительный.

## Custody и наблюдение за кошельками

Robinhood Crypto хранит активы в корпоративных адресах и не выдаёт клиентам их приватные ключи. Следовательно, наблюдение за таким blockchain-адресом не раскрывает отдельный клиентский портфель или все его покупки и продажи. Это вывод из модели custody, а не обещанная функция API. [Crypto transfers: private keys and custody](https://robinhood.com/us/en/support/articles/cryptocurrency-wallets/)

Robinhood Wallet — отдельный self-custody продукт; пользователь контролирует ключи. Он не тождественен Robinhood Crypto account. [Robinhood Wallet FAQ](https://robinhood.com/us/en/support/articles/robinhood-wallet-faqs/)

Для будущего наблюдения за внешними кошельками нужны публичные адреса, сети и отдельный chain/indexer источник. Публичная транзакция не доказывает личность владельца, его намерение или прибыльность: перевод, bridge и swap нужно различать. Нельзя приписывать агрегированные потоки кастодиана конкретному трейдеру. Seed phrase или приватный ключ для read-only наблюдения не требуется. В текущую фазу подключение кошельков не включено.

## Условия перехода к исполнению

1. Пользователь выбирает и подтверждает площадку, если официальный Robinhood EU API не появился.
2. Проверяются официальные доступность API, регион аккаунта, разрешения и актуальные условия сервиса.
3. Read-only проверка получает реальный каталог, баланс, торговые ограничения и расходы; любые отсутствующие данные блокируют исполнение.
4. Paper trading подтверждает корректность учёта комиссий, валют и состояний; прибыльность на истории не считается гарантией будущего результата.
5. Режим реальных денег включается отдельно с явно заданными суммами и лимитами. Это исследование не запускает и не разрешает сделки.
